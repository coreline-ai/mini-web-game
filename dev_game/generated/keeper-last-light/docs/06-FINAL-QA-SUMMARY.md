# 후보정 세션 #3 — 2026-08-15 (패널 재설계)

사용자 제보: "네모 이미지도 외곽이 이상한 잡음이 보이고, 텍스트도 중앙이 아닌 부분에

## 진단 — 자산이 아니라 표시 방식이 문제였다

자산을 픽셀로 재 보니 **원본은 멀쩡했다**.

| 측정 | 값 | 판정 |
|---|---|---|
| 상단 테두리 y 편차 | 3px (표준편차 1.4) | 직선에 가까움 |
| 테두리 두께 상/하 | 51 / 52 px (비 0.97) | 대칭 |
| 테두리 두께 좌/우 | 33 / 34 px (비 0.97) | 대칭 |
| 안쪽 필드 중심 | 세로 49.8% / 가로 50.0% | 정중앙 |

문제는 `setDisplaySize`였다.

| | 값 |
|---|---|
| 원본 비율 | 1024×512 = **2.00 : 1** |
| 표시 비율 | 1062×234 = **4.54 : 1** |
| 실제 배율 | 가로 **1.037배** / 세로 **0.457배** |
| 표시 후 테두리 | 상하 23px vs 좌우 34px — **좌우가 1.47배 두꺼움** |

가로·세로를 2.3배 다르게 늘렸으니 모서리 라운딩은 타원이 되고 금속 베벨은 세로로 절반이
되어 얼룩처럼 보였다. 사용자가 "외곽 잡음"이라 부른 것이 이것이다.

두 번째 지적("텍스트가 중앙이 아님")은 별개 원인이다: 행 위치를 고정 오프셋으로 잡아 둬서,
**입력 전에는 비어 있는 버퍼 줄이 자리를 차지한 채** 보이는 내용만 위로 쏠렸다.

## 수정 — 9-slice (계약 §2.0.5가 지정한 방식)

계약은 이미 UI에 "9-slice 또는 비율 고정"을 요구하고 있었다. `setDisplaySize`로 비율을
깨뜨린 것 자체가 계약 위반이었다.

- `add.nineslice()`로 교체. 모서리 크기는 자산의 평평한 안쪽 필드가 시작되는 지점(실측
  좌 73 / 우 74 / 상하 76), 배율 0.4로 테두리가 화면에서 10 CSS가 되게 했다.
- 결과 테두리: 좌우 9.7 CSS / 상하 10.1 CSS — 사실상 균일.
- 패널 높이 78 → 88 CSS, 중심 0.745 → 0.755, 램프 0.885 → 0.895 (충돌 재검산 완료)

**동적 정렬** — `layoutPanelRows(hasBuffer)`가 보이는 행 수로 y를 다시 잡는다.
입력 전에는 코드행이 필드 정중앙(1912), 입력 중에는 두 행이 중심 기준 ±36으로 대칭.
