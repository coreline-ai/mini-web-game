# 02-TECH-DESIGN — Last Minute Keeper

## 씬

| 씬 | 역할 |
|---|---|
| Boot | Phaser 부팅 |
| Loading | 첫 배경 + 스프라이트 + UI + FX + SFX 로드. 나머지 배경·BGM은 홈 진입 후 지연 로드 |
| Home | 첫 플레이 5요소 선언, 사운드 토글, 최고 점수 |
| Game | 커스텀 루프 전부 |
| Pause | 일시정지 + 도움말(같은 오버레이, `data.help`로 분기) |
| GameOver | 승/패 터미널, 점수·세이브·실점·도달 스테이지 |

## 좌표계

논리 캔버스 **1170×2532** = 390×844의 정확히 3배. Phaser 3.60+에는 `resolution`이 없어
논리 캔버스가 곧 백킹 스토어이므로, CSS 크기와 같게 두면 전체가 1x로 그려진 뒤 브라우저가
확대한다. `config/theme.js`의 `U = width/390`과 `px()`/`font()`가 단일 원본이며 화면 안의
모든 절대 픽셀값은 이를 거친다. `visual-layout-qa`의 backingScale assert가 이 계약을 검사한다.

## 시스템

| 파일 | 책임 |
|---|---|
| `config/keeperConfig.js` | **Rules Contract 단일 원본** — 조작 임계, 슛 종류, 스테이지 계약, 점수, 리바운드 상한 |
| `config/spriteMetrics.js` | 텍스처별 **알파 여백 실측값**. 스프라이트 경계가 아니라 실제 몸통 기준으로 UI·그림자를 붙인다 |
| `config/theme.js` | 디자인 단위 U, §2.0.25 버튼 토큰, 테마 파생 팔레트 |
| `systems/BallPhysics.js` | 속도·중력·마그누스 곡률·반사, 높이(그림자 거리) 계산 |
| `systems/KeeperController.js` | 드래그 이동(최고 속도·관성), 플릭 판정, 다이브 상태 기계, 회복 중 입력 차단, 멀티터치 차단 |
| `systems/ShotDirector.js` | 슛 종류 선택, 백스윙 예고, 스테이지별 빈도·동시 공 상한 |
| `systems/SaveJudge.js` | 키퍼 body ↔ 공 충돌, 세이브 등급 판정, 리바운드 벡터 산출 |
| `entities/Ball.js` | 공 생명주기(비행 → 세이브/실점 → 리바운드 → 퇴장), 고정 풀 |
| `entities/Keeper.js` | 자세 전환(대기/다이브/캐치), 판정 body 갱신 |
| `entities/Shooter.js` | 백스윙 연출, 슛 발사 지점 |

## 판정 흐름

```
ShotDirector가 슛 예고 → Shooter 백스윙 트윈 → Ball.launch(type, targetX)
  ↓ 매 프레임
BallPhysics.step()  속도 + 중력 + 마그누스 곡률 → 위치, 높이, 그림자
  ↓ 골라인 통과 직전
SaveJudge.test(keeperBody, ball)
   맞음 → 등급 판정(캐치/펀칭/다리) → 점수·콤보 → 리바운드 벡터
   빗나감 → 실점 → 네트 출렁임 FX + 카메라 흔들림 + 관중 탄식
```

## 높이 표현 — 원근 없이

세로 2D에서 "공이 높이 떠 있다"를 원근으로 표현할 수 없으므로 두 신호를 쓴다.

1. **공 크기** — 높을수록 크게 그린다(가까이 오는 착시)
2. **그림자 거리** — 지면 그림자를 공보다 아래에 그리고, 높이에 비례해 간격을 벌린다

로빙은 그림자가 눈에 띄게 멀어져 "머리 위로 넘어온다"가 읽힌다.

## 생명주기 규약 (결함 클래스 A)

- 상태 전이는 **트윈 `onComplete` 안에서만**. 비행 트윈이 끝나기 전에는 리바운드로 넘어가지 않는다
- 재사용 시 `killTweensOf` + 알파/각도/스케일/가시성 전체 리셋
- 퇴장 확정(`retired`)한 공은 판정·점수·충돌에서 완전히 제외
- 고정 풀이라 리트라이를 반복해도 오브젝트가 누적되지 않는다(클래스 K)

## 시각 소유권 (클래스 B)

| 대상 | 소유 |
|---|---|
| 골대 프레임·네트·잔디·관중·조명탑 | **배경 이미지** |
| 공·그림자·키퍼·공격수·수비수 | **런타임 스프라이트** |
| 임팩트·장갑 섬광·네트 출렁임·잔디 튐·빗줄기 | **런타임 FX** |

배경 프롬프트에 "골 안은 완전히 비어 있을 것 — 공·골키퍼·선수 없음"을 명시해 이중 소유를
원천 차단했다.

## 물리 경계 (클래스 M)

키퍼의 판정 body는 자세마다 다르다. 대기 자세는 몸통 폭, 다이브 자세는 뻗은 팔까지 포함해
가로로 `diveReachMultiplier`배 늘어난다. **보이는 스프라이트와 body가 어긋나면 "닿았는데 안
막힌다"가 되므로**, 두 상태의 body를 캡처로 검증한다.

## 상태 흐름

```
Boot → Loading → Home ─PLAY→ Game ⇄ Pause(일시정지/도움말)
                                 ├─ 스테이지 5 종료 → GameOver(win)
                                 └─ 실점 5회        → GameOver(loss)
                          GameOver ─RETRY→ Game (스테이지 1부터 완전 초기화)
```

## QA 훅

`GameScene.qaSnapshot()`이 점수·콤보·실점·세이브·스테이지·살아있는 공 목록·키퍼 상태·
활성 트윈/타이머·오디오 스냅샷을 반환한다. 캡처 어댑터가 이것을 상태 샘플로 기록한다.
