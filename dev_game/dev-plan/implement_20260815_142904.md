# implement_20260815_142904.md

작성 일시: `2026-08-15 14:29:04 KST`

스킬 능력을 최대 폭으로 사용하는 데모 게임 **「등대지기: 마지막 항로」(Keeper of the Last Light, `keeper-last-light`)** 의 제작 계획.

## 왜 이 조합인가 — 커버리지가 주제를 결정했다

자유 주제이므로 "재미있어 보이는 것"이 아니라 **파이프라인에서 아직 한 번도 같이 돌아본 적 없는 경로**를 기준으로 골랐다. 현재 저장소의 실측 상태가 선택 근거다.

| 실측 | 이번 데모가 하는 일 |
|---|---|
| 자산 438개 중 **영수증 보유 0건** (435 legacy-1 + 3 파생) | Path A 전 구간을 새로 돌려 **저장소 최초의 영수증 보유 게임**을 만든다 |
| v2 custom-loop 게임 3개 중 Path A는 1개뿐 | v2 custom-loop + Path A 조합을 정면으로 검증 |
| 게임 17개 중 14개가 후보정 게이트 **미적용**(v1) | v2를 택해 `custom-loop-full-qa` 8종 검사를 전부 통과시킨다 |
| 생성 검증·재시도·크로마 정화·WebP 수출이 실게임에서 한 번도 완주된 적 없음 | 배경·스프라이트·UI·FX 4개 그룹을 모두 생성해 4개 루프를 전부 태운다 |

즉 이 데모의 목적은 "게임 하나 더"가 아니라 **오늘 만든 것들이 실제로 작동하는지 실사용으로 증명하는 것**이다. 직전 계획들이 "다음 수정은 실사용 실패가 지시한다"로 끝났으므로, 그 실사용이 이 문서다.

## 게임 설계

### 한 줄 피치
안개 낀 바다에서 등대 불빛으로 **신호 코드**를 보내 배를 안전 항로로 인도하고, 여명까지 버틴다.

### 핵심 루프 (30초)
1. 수평선에 배가 나타나고 머리 위에 **요청 기호**가 뜬다 (예: 좌현 변침 / 감속 / 정박 대기)
2. 각 기호는 **빛 코드**에 대응한다 — 짧게(▪) / 길게(▬) 3~5개 조합
3. 플레이어가 램프 버튼을 그 리듬대로 탭·홀드한다
4. 정확하면 배가 항로로 진입(점수+콤보), 틀리거나 시간 초과면 암초로 표류
5. 난파 3회 → 실패 / 여명(5스테이지 통과) → 승리

### 왜 리스킨이 아닌가
기존 17개는 사격·레이싱·물류·지휘·조리 계열이다. 이 게임의 입력은 **조준도 이동도 아닌 시간축 위의 패턴 입력(짧게/길게)** 이고, 핵심 시스템(`SignalCodec`, `PatternInput`, `ShipRouting`)은 어느 아키타입에도 없다. schema v1 어휘(낙하 hazard + collectible + 좌우 이동)로는 표현 자체가 불가능하므로 v2 custom-loop가 유일한 경로다.

### 계약 정합 설계 (결함 클래스 사전 차단)
- **클래스 D**: 난이도 입력은 `elapsed`와 스테이지 인덱스만 — 플레이어가 회복 가능한 자원(남은 시간·연료)을 난이도 축으로 쓰지 않는다.
- **클래스 E**: 스테이지마다 (목표 척수, 보상, 다음 상태)를 config 데이터로 선언하고, **승리·패배 양쪽 터미널을 모두 도달 가능**하게 한다.
- **클래스 B**: 등대 탑·암초는 배경이 소유하고, 배·광선·물보라만 런타임이 소유한다(이중 소유 금지).
- **클래스 C**: 화면의 모든 사각형/선은 의도된 렌더로 문서화하거나 삭제한다. 신호 패널은 UI로 명확히 구분한다.
- **클래스 H/I/J/K**: BGM 단일 핸들, 전환 버튼 one-shot, 저장 복구, 씬 shutdown 정리를 셸 기본값 위에 유지한다.

### 첫 플레이 이해도 (first-play-clarity 대응)
목표(여명까지 버티기) · 승패 조건 · 첫 행동(램프를 탭) · 진행 지표(스테이지/난파 카운트) · 도움말 정지·재호출을 모두 화면에 선언한다. 신호 코드표는 항상 열람 가능해야 한다.

## 에셋 계획 (4개 그룹 전부 — 생성 루프 완주가 목적)

| 그룹 | 항목 | 파이프라인에서 검증되는 것 |
|---|---|---|
| 배경 ×5 | 맑은 밤바다 / 옅은 안개 / 짙은 안개 / 폭풍 / 여명 | 엣지분산 검증, Declared Resample, 런타임 WebP 1440×3120 수출, tier 승격(3종 이상) |
| 스프라이트 | 화물선·어선·여객선·난파선 | 크로마 제거 → 3px 침식 → 자홍 중화 → 알파/채움비 검증 |
| UI | 램프 버튼(대형)·일시정지·도움말·신호 코드 패널·진행 게이지 | **버튼 hue 검증 + 재시도**(테마 액센트 거리), §2.0.25 버튼 규격 토큰 |
| FX | 광선 펄스·성공 링·난파 섬광·물보라 | 소형 자산 알파 규칙, 384px 런타임 수출 |

**시트는 opt-in하지 않는다.** 다프레임 시트는 구조적 실패율이 높다고 확인된 주문이므로 배는 단일 스프라이트 + 트윈으로 움직인다. 이는 계약이 정한 기본값을 그대로 따르는 것이다.

오디오: 무적(foghorn) BGM, 파도 앰비언트, 램프 클릭, 성공/실패 차임, 난파 충격음.

## 잔여 리스크

- **아트 생성 시간**: 자산 18개 × 최대 3시도 × ~40초 = 최대 30분대. 백그라운드 실행과 재개 규약을 반드시 지킨다.
- **패턴 입력의 가독성**: 짧게/길게 구분 임계가 너무 엄격하면 재미가 아니라 스트레스가 된다. 임계는 config로 빼고 캡처 검토에서 조정한다.
- **v2 custom-loop 어댑터 작업량**: 캡처 어댑터는 게임마다 새로 쓴다. 기존 3개 v2 게임의 어댑터를 참고 패턴으로 삼되 복사하지 않는다.
- 이 데모가 실패하면 그 실패 자체가 **파이프라인의 다음 수정 지시**다 — 실사용 실패가 종료 조건이라는 직전 계획의 원칙이 여기서 작동한다.

## 대안 주제 (같은 커버리지를 원할 경우 교체 가능)

| 주제 | 커스텀 시스템 | 비고 |
|---|---|---|
| 조난 신호 삼각측량 구조대 | 방위각 회전·오차 수렴·구조 파견 | 정밀 드래그 입력, 지도 UI 비중 |
| 지진 관측소 대피 지휘 | 파형 판독·구역 대피·여진 예측 | 데이터 시각화 비중이 커서 아트 그룹 편중 |

두 대안 모두 v2 custom-loop가 필요하고 4개 에셋 그룹을 쓰지만, 등대 쪽이 **배경 5종(날씨 변화)**을 자연스럽게 요구해 스테이지 배경 검증과 tier 승격 경로를 가장 확실히 태운다.
