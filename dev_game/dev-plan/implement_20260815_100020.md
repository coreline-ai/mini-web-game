# implement_20260815_100020.md

작성 일시: `2026-08-15 10:00:20 KST`

이 문서는 **생성기 템플릿의 UI 품질 결함**(버튼 규격 부재·테마 무관 하드코딩 색상)과 **이전 워크스트림에서 남긴 예제 스펙 정리**의 범위를 고정하는 작업 문서다. 대상은 특정 게임이 아니라 `dev_game` 생성기이며, 여기서 고치면 이후 만들어지는 모든 게임에 적용된다.

## 개발 목적

- 버튼이 **호출부마다 다른 크기**로 만들어지는 구조를 없애고, 규격 토큰으로 통일한다.
- 버튼 색이 게임 테마와 무관하게 **항상 초록**인 두 겹의 하드코딩(imagegen 프롬프트 + 절차적 폴백)을 제거하고, `spec.theme.colors`에서 파생시킨다.
- 파생 규칙은 "배경과 같은 색상 계열로 **통일감**을 주되 명도/채도 대비로 **구분**되게"로 정의한다.
- 이전 워크스트림([implement_20260815_081201.md](implement_20260815_081201.md))에서 남긴 예제 스펙 7개의 DPR 미달 캔버스를 정리한다.

## 개발 범위

- `dev_game/generator/src/cli.mjs`: 버튼 규격 토큰(`BUTTON`), 테마 파생 팔레트 함수, `MobileButton` 절차적 폴백의 테마화, 호출부 6곳을 토큰으로 교체

- 회귀 검증: 신규 스캐폴드 + 기존 게임 게이트

### 설계
```js
// tuning.js — 390x844 디자인 단위 기준, 사용 시 U 환산
export const BUTTON = {
  primary:   { width: 230, height: 64 },  // PLAY, RETRY, RESUME — 화면당 1개
  secondary: { width: 230, height: 54 },  // SOUND, HOME — primary와 같은 폭, 낮은 높이
```

## Phase 2. 테마 파생 버튼 팔레트

### 목표
- 버튼 색을 `spec.theme.colors`에서 파생시켜, 어떤 게임이든 배경과 통일감을 유지하면서 구분되게 한다. 초록 하드코딩 2곳을 모두 제거한다.

### 파생 규칙 (제안)
액센트 색을 `theme.colors.collectible → player → ui` 순으로 고르고, 배경 명도에 따라 방향을 정한다.

| 요소 | 규칙 |
|---|---|
| face | 액센트 색 |
| shadow | face를 명도 −35% (테두리/바닥) |
| highlight | face를 명도 +25% (상단 하이라이트) |
| label | 배경이 어두우면 `theme.colors.ui`(밝은 색), 밝으면 어두운 대비색 |

**통일감**: 색상환에서 배경과 같은 계열의 액센트를 쓰므로 이질적이지 않다.
**구분**: 배경 대비 명도차를 강제한다 — 대비비가 기준 미만이면 액센트 명도를 조정한다.

## 잔여 리스크 / 후속 과제

- 이미 생성된 16개 게임의 버튼은 이 변경으로 자동 개선되지 않는다. 각 게임의 `game-polish` 세션에서 재생성해야 하며, 그때 Phase 2의 파생 규칙을 따른다.
- 테마 파생 규칙은 액센트 색이 배경과 지나치게 가까운 팔레트(예: 배경도 금색, 액센트도 금색)에서 대비가 부족할 수 있다. 대비 보정 로직이 이를 처리하지만, 극단적 팔레트는 캡처 확인이 필요하다.
- 버튼 외 UI(패널·티켓·인내심 바)는 여전히 하드코딩 색을 쓴다. 같은 원리의 후속 과제로 남긴다.
