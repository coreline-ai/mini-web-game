## 공통 진행 규칙

- 각 Phase는 첫 편집 전에 간단한 PLANNED 증거 파일을 만든다.
- 구현 후 같은 파일에 As-built, 실행 명령, 실제 출력 요약, 계획 밖 변경을 기록한다.
- 적용 스킬·권위 계약과 양방향 대조한 뒤 자체 PASS를 기록한다.
- 다음 Phase는 앞 Phase 자체 테스트가 전부 통과한 뒤 시작한다.
- fixture는 정상 입력 GREEN과 알려진 결함 RED를 모두 가진다. RED는 종료 코드와 실패 사유를 함께 확인한다.
- 검사 대상이 커밋됐는지 dirty인지에 따라 결과가 달라지면 안 된다.
- 계획 밖 결함은 현재 작업에 섞지 않고 이슈 절에 기록한다.
- 독립 reviewer PASS는 이 실행에서 주장하지 않는다. 최종 결과는 `자체 검증 PASS`로만 표기한다.
