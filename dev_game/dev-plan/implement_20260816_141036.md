## 개발 목적

| reference/계약 | 수치·예외·긴 사례·개별 게이트 |
| script/template | 반복되는 결정적 검사·산출물 |

inventory는 `SKILL.md`만 보지 않고 각 스킬 디렉터리 전체의 `agents/`, `references/`, `scripts/`,
`assets/`와 SKILL에서 가리키는 링크까지 검사한다.

## 작업 유형과 정합성 판정

- `skill-execution`: 적용 skill SHA를 동결하고 작업 중 skill 변경을 금지한다.
- `skill-maintenance`: `baseline SHA`, 사전 고정 target contract/corpus, `candidate SHA`를 대조한다.
- 현재 계획은 `skill-maintenance`이므로 스킬 변경 자체는 허용하되 후보가 자기 기준을 만들 수 없다.

```text
PLANNED → IMPLEMENTING → EVIDENCE_READY → ADVERSARIAL_REVIEW → PASS → NEXT
                                                └→ BLOCKED
```

이 계획에서는 `USER-WAIVER`로 Phase PASS를 대체하지 않는다. 향후 일반 절차에 waiver를 넣을
경우에도 사용자 원문·일시·task·편차·영향·만료를 기록하고, 증거 누락·범위 밖 변경·검사기
fail-open은 면제할 수 없다.

## 명령 검사기 안전 계약

`check_skill_commands.mjs`는 현재 정확히 7개를 보고하지만 `factory:qa`를 실제 실행해 자기 자신을
재호출하고, 두 번의 timeout과 spawn 실패를 무시한 채 GREEN이 될 수 있다. Phase 1에서 먼저
다음 계약으로 고친다.

- target factory 명령을 실제 실행하지 않는다. aggregate `factory:qa`는 package 등록만 정적 확인한다.
- CLI 인자는 부작용 없는 help/구조화 metadata 또는 분리한 parser로 검사한다.
- `spawnSync.error`, timeout, signal, 실행 파일 없음, 비정상 종료는 RED다.
- `--skills-root <fixture-dir>` 또는 동등한 fixture 주입 경로를 제공한다.
- 남은 placeholder와 skipped command가 하나라도 있으면 RED다.
- 단순 총수 외에 `skill + command ID + 책임`의 필수 7개 inventory를 고정한다.
- `checked >= 7`은 공허 통과 방지 보조 assert일 뿐 다이어트 품질 판정이 아니다.
- asset/motion의 명령 수가 0이어도 다른 스킬 명령으로 그 Phase 품질을 증명했다고 보고하지 않는다.

## 공통 진행 규칙

- 한 번에 하나의 Phase와 하나의 주 스킬만 진행한다.
- Phase 1 게이트·fixture가 PASS하기 전에는 어떤 스킬도 다이어트하지 않는다.
- 자동 검사는 구조·회귀 방지용이며 다이어트 품질은 독립 대조표가 판정한다.
- 승인 계획 본문은 읽기 전용이며 현재 Phase 체크박스만 갱신한다.
- Phase 종료 후 As-built와 증거를 기록하고 독립 reviewer에게 넘긴다.
- 계획 밖 변경은 후속 후보로 기록하고 현재 작업에 섞지 않는다.
- 기존 변경을 자동 복구·덮어쓰기·커밋하지 않는다.
- 새 의존성을 추가하지 않는다.
- 체크박스는 실행 증거와 reviewer PASS가 있을 때만 닫는다.
