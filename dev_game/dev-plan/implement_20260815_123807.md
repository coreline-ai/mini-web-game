## 개발 목적

- 승격 조건을 **증명 기반**으로 강화한다: 영수증(`outputSha256` 실일치 + `runId` + `generatedAt`) 또는 명시적 레거시 표기(`provenanceVersion: "legacy-1"`)가 있어야만 production-demo.
- `production-demo-qa`가 영수증을 **실제 파일 해시와 대조**하게 한다. 영수증 도입 이전 자산은 legacy-1 표기로만 통과한다 — 미표기·미영수증은 실패.
- 기존 추적 게임 전체를 legacy-1로 마이그레이션한다(소급 증명 불가를 명시적 상태로 전환).
- Path B 계약에 영수증(`outputSha256`)을 필수로 추가한다.
- `--only wire`가 "외부 복원 에셋도 승격"한다고 서술하는 문서 모순을 수정한다.
- 무결성 로직 전체(비정상 종료·정체 출력·무영수증·SHA 불일치·레거시·custom-loop 무Codex)를 **자동 회귀 테스트**로 만들어 `factory:qa`에 편입한다.

## 잔여 리스크 / 후속 과제

- legacy-1은 증명이 아니라 **증명 불가의 명시**다. 위조자가 legacy-1을 손으로 쓸 수 있으나, 이 시스템의 신뢰 경계는 원래 "정직한 프로세스의 무결성"이며 적대적 공격 방어가 아니다(기존 문서화 유지). 신규·재생성 자산은 영수증만 인정되므로 시간이 갈수록 레거시 비중은 줄어든다.
- 게이트 SHA 대조는 자산 수만큼 해시를 계산한다(게임당 ~20파일, 수십 ms) — 무시 가능.
- iron-courier-last-line은 본 워크스트림 이전부터 게이트 RED(공유/타게임 provenance.source 위반, player-shoot-polished 외 2건). 영수증 체계와 무관한 별건 — 해당 게임 자산 재생성 세션에서 해소할 것.
