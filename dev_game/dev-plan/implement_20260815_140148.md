## 배경 — iron-courier 실패의 진짜 원인

게이트 에러만 보면 "공유 자산 사용"으로 읽히지만, 실물을 확인하니 **다른 게임에서 가져온 자산이 아니었다.**

| 자산 | source | method |
|---|---|---|
| `player-shoot-polished` | `derived-from-approved-runtime-asset` | `deterministic-position-only-repack` |
| `player-run-fire-actions` | `derived-from-approved-runtime-assets` | `identity-locked-upper-lower-composite` |
| `player-air-fire-actions` | `derived-from-approved-runtime-assets` | `identity-locked-upper-lower-composite` |

셋 다 **이 게임 자신의 승인된 자산**(`player-run`, `player-movement-actions`, `player-combat-actions` — 모두 `generated-for-game`)을 결정적으로 재조합한 파생물이다. 캐릭터 동일성(identity-lock)을 유지하려면 재생성이 아니라 기존 프레임 합성이 정답인 정당한 제작 기법이다.

즉 이것은 **게임의 결함이 아니라 계약의 어휘 부재**다. 계약에 "이 게임 자신의 자산에서 파생"이라는 상태가 없어서, 정당한 파생물이 금지된 공유 자산과 같은 취급을 받았다.

따라서 조치는 "자산을 다시 만든다"가 아니라 **"파생 자산을 계약의 1급 시민으로 정의한다"**이다. 재생성은 identity-lock을 깨뜨려 품질을 오히려 떨어뜨린다.

## Phase A. 파생 자산 계약 + iron-courier 정정

### 설계

허용 provenance 형태를 하나 추가한다:

```jsonc
{
  "source": "derived-from-generated-for-game",
  "generatedFor": "<이 게임 id>",
  "derivedFrom": ["player-run", "player-combat-actions"],
  "method": "identity-locked-upper-lower-composite",
  "postProcessing": [ ... ]
}
```

게이트 규칙:
1. `source`는 `generated-for-game` 또는 `derived-from-generated-for-game`만 허용
2. 파생이면 `generatedFor`가 게임 id와 일치 + `derivedFrom`이 비어 있지 않은 배열
3. `derivedFrom`의 모든 id가 **같은 manifest 안에 존재**하고, 그 부모가 `generated-for-game`이거나 (재귀적으로) 증명된 파생일 것 — 순환은 에러
4. 파생 자산에는 imagegen 필드를 요구하지 않는다(출처는 부모가 증명)
5. `reusedFrom`/`copiedFrom`/`sourceProject`/외부 서비스 필드 금지는 파생에도 그대로 적용
