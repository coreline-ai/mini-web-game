# 독립 검토 — gate-boot-diagnostics

- reviewer: `production-pass-receipt-qa` (기계 판정) + GL 경로 비교 측정
- 판정: `PASS`

## 검토자가 실제로 확인한 것

1. **원인이 값으로 나왔다.** 계측 후 첫 실패의 진단이 `rafTicks=725 loop=stopped frame=0
   game=booted glLost=false glError=0`이다. 이 조합은 "브라우저는 프레임을 주는데 Phaser 루프가
   시작되지 않았다"만 의미한다 — 추측의 여지가 없다.
2. **수정이 측정으로 뒷받침된다.** `--use-gl=swiftshader` 9/10 → `--use-angle=swiftshader`
   22/22(visual-layout). n이 작은 단일 비교가 아니라 오늘 누적된 `gl` 실패들(3/8, 6/8, 5/6, 9/10)과
   대비된다.
3. **플레이크를 체계적 실패로 바꾸지 않았다.** 렌더러 교체는 픽셀 판정을 흔들 수 있으므로
   `scene-composite`의 픽셀 검사를 12/12로 따로 확인했다. 이 확인이 없으면 승인하지 않았다.
4. **되돌릴 수 있다.** `GAME_QA_GL=gl`이 남아 있어 다음 사람이 같은 비교를 재현할 수 있다.
   대조군이 그 스위치의 양방향을 각각 단독으로 고정한다.
5. **범위를 넓히지 않았다.** 같은 하드코딩이 게임 어댑터에도 있지만 선언 범위 밖이라 손대지 않고
   구현 기록에 후속으로 남겼다. 오늘 이 저장소는 범위를 넓히는 대신 구현을 좁히는 선택을 두 번 했다.

## 남는 위험

`--enable-unsafe-swiftshader`는 이름이 말하듯 소프트웨어 렌더링을 강제하는 플래그다. QA
전용 경로이며 배포물에는 영향이 없다. 다만 Chromium이 이 플래그를 또 대체하면 같은 종류의
플레이크가 재발할 수 있다 — 그때 원인을 다시 추측하지 않도록 계측과 `GAME_QA_GL` 스위치를
남겨 두는 것이 이 task의 절반이다.

또한 이 수정은 **게임 어댑터 단계의 플레이크를 닫지 않는다.** v2 게임의 `test:*` 어댑터는
여전히 옛 GL 경로를 하드코딩한다. 게이트 전체 통과율은 그만큼 남아 있다.
