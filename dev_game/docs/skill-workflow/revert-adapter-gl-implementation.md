# 구현 기록 — revert-adapter-gl

## 되돌린 것

게임 QA 어댑터의 GL 경로 변경을 **4개 게임 전부에서 되돌린다**(커밋 7226b4f, 0b5a784).
각 게임의 `qa/*.mjs`는 다시 `--use-gl=swiftshader`를 쓰고, 추가했던 `qa/_browser-args.mjs`는 지운다.

**생성기 도구(`visual-layout-qa`·`scene-composite-qa`)의 ANGLE 전환은 유지한다** — 그쪽은
측정된 개선이다(9/10 → 22/22, 픽셀 검사 12/12).

## 왜 되돌리나 — 이득은 미측정, 해악은 측정됐다

어댑터 레벨 변경의 근거는 "같은 플래그, 같은 환경, 확인된 기전"이었다. 이득은 측정되지
않았고(keeper 어댑터 gl 10/10 vs angle 10/10, 판별력 부족) 그 상태로 4개 게임에 적용했다.

그 뒤 skybreak-gunship의 게이트가 2회 연속 같은 지점에서 떨어졌다:

```
qa/clarity-qa.mjs:76  check(gunResult.step === 2 && gunResult.shots >= 3)
실측: {"step":1,"combo":1,"shots":1}
```

파일을 건드리지 않고 환경변수만 바꿔 A/B를 돌렸다(같은 프리뷰, 같은 코드):

| GL 경로 | `qa/clarity-qa.mjs` |
|---|---|
| `gl` (기존) | **3/3 통과** |
| `angle` (변경) | **1/3** — 실패 시 `shots:2` (요구 ≥3) |

ANGLE에서 프레임 타이밍이 달라져 고정 대기 구간의 발사 횟수가 요구치에 못 미친다. 즉 어댑터
레벨에서 이 변경은 **이득 0, 회귀 1건**이다. 증거가 기전보다 우선한다.

## 남는 혼재를 인정한다

이제 생성기 도구는 ANGLE, 게임 어댑터는 옛 경로다. 원래 이 변경의 근거 중 하나가 "혼재 제거"였고,
그것은 잃는다. 다만 혼재는 진단을 어렵게 하는 비용이고 회귀는 게이트를 깨뜨리는 비용이다 —
후자가 크다. 혼재 사실을 계약 K-2의 "아직 남은 곳"에 이미 적어 두었으므로 다음 사람이 모르고
시작하지는 않는다.

## 어댑터를 ANGLE로 옮기려면 (다음 사람에게)

플래그만 바꾸는 것으로는 안 된다. 어댑터의 단정이 **프레임 타이밍에 의존**하기 때문이다.
같이 해야 하는 일: 고정 대기 대신 기대 상태를 기다리도록(`waitForFunction`) 단정을 바꾸고,
게임마다 어댑터 전체를 두 경로에서 각각 N회 재서 회귀가 없음을 확인한다. 그 작업 없이 옮기면
오늘과 같은 일이 반복된다.

## 검증

되돌린 뒤 4개 게임을 재게이팅해 영수증을 다시 발급한다 — 결과는 이 문서가 아니라 그 영수증이
증명한다.
