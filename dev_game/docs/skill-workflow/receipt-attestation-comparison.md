# 스킬·계약 정합성 비교 — receipt-attestation

| 요구 | 실제 | 판정 |
|---|---|---|
| 영수증은 게이트 통과로만 발급 | CI가 게이트 뒤에만 서명. 서명기는 영수증을 만들지 않는다 | MATCH |
| 라우팅을 바꾸려고 증거를 만들지 않는다 | 손으로 쓴 영수증이 공개키 커밋 후 `invalid` | MATCH |
| 첫 PASS는 저장소가 공유하는 사실 | 공개키가 저장소에 있어 누구나 검증 가능 | MATCH |
| 한계를 해결된 것으로 표기하지 않는다 | 키 없으면 `unattested`로 명시, 켜는 절차와 부작용 기록 | MATCH |

## 라우팅 영향

현재는 변화 없음 — 공개키를 커밋하지 않았으므로 8개 `pass`가 그대로다. 상태 문구에만
`(unattested — no signing key committed)`가 붙어 **지금이 전환 전임을 스스로 말한다.**
